## 怎么核出来的（可复算）

三层证据，逐层都能自己跑：

1. **菜单算法**：`build/payload/resources/app.asar` → `runtime/electron-helper/shared-core.js` 的 `buildMenuTree()`（v0.4.9，171,994 字节 / 5,315 行）与 `EVENT_LABELS`。三级结构、二级组顺序、事件组标签映射均取自该函数原文。
2. **配置侧一致**：把同一套算法分别跑在仓库 `packs/*.json` 与安装包内的 `build/payload/userdata/.dsh/dsh-pet/pet/<pet>-config.json` 上，三只的分组名、每组动作名集合**完全相同**（三只「组名只在 packs / 只在 payload / 同名但内容不同」三个差集全为空集）。
3. **素材侧一致**：每个宠物目录 `<pet>-animation/` 下的 `.webm` 文件名集合，与该宠物菜单里不重名的动作名集合**双向相等**（92 / 166 / 100，零缺件、零孤儿文件）。跨宠物有同名文件（gpt∩claude 56、gpt∩gemini 60、claude∩gemini 72），但各自落在独立目录里，不共用。

## 边界（必读）

- 全部是**静态取证**：代码原文 + 配置文件。菜单在 Windows 真机上长什么样、展开手感、是否折叠，**一次都没点过**。
- 菜单里显示的是配置里的原名，带前缀的照原样显示（例如 `点击回应-元气挥手`、`余额-分文不剩`、`工作状态-忙碌点按`）。
