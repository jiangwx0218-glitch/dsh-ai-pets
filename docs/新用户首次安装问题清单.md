2. **DSH 图形界面路径**：本机没有 DSH 桌面 App，也没有 `dsh web`。所以「设置 → 插件 → 添加插件 → 粘贴仓库地址」这条路**一步都没走**。问题 1 里关于图形界面的结论，来自 README 文本本身（图形界面那段确实没有 dsh-pet 这一步），不是来自实操。
3. **重启之后的效果**：硬约束不允许启动/重启 DSH，所以「重启后桌面右下角真的出现三只」完全没验证。所有「装完」的结论只到「文件落到 `<DSH_HOME>/dsh-pet/pet/` 里、目录结构和动作数对得上」这一层；**dsh-pet 能不能真的加载它们、窗口能不能弹出来，未验证**。
4. **`ffmpeg` 相关**：本机没有 ffmpeg。README 里 `scripts/build-release.mjs`（精灵图 → webm）那条链路没跑过；「透明视频 VP9 + yuva420p + ALPHA_MODE=1」「Safari 不支持 alpha webm」这些说法未验证。
5. **README「开发」节**：`node scripts/build-release.mjs --out dist …` 和 `./scripts/publish.sh v0.1.0` 都没跑（后者会发 Release，禁止）。`scripts/check-packs.mjs` 也没跑——它不在本轮"新用户安装"范围内。

### 是「模拟」而不是真实验证的

6. **所有下载都不是从 GitHub 下的**。`baseUrl` 一直指向本机 `python3 -m http.server --directory dist`，走的是 localhost + 仓库现成 `dist/*.tar.gz`。所以：真实 GitHub Release 的 `latest/download` 是否会 302 到 objects.githubusercontent.com、真实带宽多快、真慢网/断网长什么样，**全都没验证**。问题 4 里「10MB/s / 1MB/s 大约多久」是我按 126MB 除出来的**估算**，不是实测。
7. **「源不回包」「极慢」「包被换掉」三种坏源是我自己造的**：`hang-server.js`（接受连接永不回包）、`slow-server.js`（每 2 秒发 1 字节）、`badsrc/gpt.tar.gz`（26 字节假文件）。它们复现的是**插件对这些异常的反应**，不等于真实 GitHub/CDN 故障时一模一样。
8. **问题 3 有一个关键点只做到「≥90 秒」**：源不回包时，我实测到「90 秒零输出、进程不退出，需要外部 kill」。**它会不会在更长时间后自己超时退出（底层 fetch 可能存在约 5 分钟量级的默认超时），我没有等满，未验证**——所以「永远卡住」这个结论我不下；能说的是「前 90 秒一片空白，且没有任何提示告诉用户该等多久或该怎么办」。
9. **日志文本的保真度**：输出由 `test/apply-smoke.mjs` 的假 ctx（`logger(level, msg)` → `console.log(msg)`）产生。行**内容**与插件源码里拼的字符串一致，但真实 DSH 的 logger 可能自带时间戳、级别、插件名前缀，**不保证与用户在 DSH 里看到的字节级相同**。
10. **场景 2 的 `Warning: Detected unsettled top-level await` 和 `[exit=13]` 是冒烟脚本的产物，不是插件输出**：`test/apply-smoke.mjs` 把 `全部处理完毕` 当完成信号，而「没有 dsh-pet 目录」分支提前 `return`，所以脚本永远等不到、Node 以 13 退出。用户真在 DSH 里跑不会看到这两行。**但这件事本身是个连带问题**：既然冒烟脚本也把 `全部处理完毕` 当成功信号，那么 404 失败（问题 2）和 sha256 失败在这套冒烟里同样是 `[exit=0]`「通过」——真实跑出来的两条都证实了这一点。也就是说这套冒烟测不出「装失败」。
11. **`only` 与 `autoInstall` 的其他组合**没穷举：只跑了 `only` 单只、`only` 拼错、`autoInstall:false` 三种。`only` 里同时写三只中的两只、`only` 为空数组、`baseUrl` 为空串等边界未测。
12. **`marginX` 负数导致窗口出屏幕**、**素材路由 `cache-control: max-age=3600`**：README 提了，但都需要真 DSH 才能验证，未测。
